# Physical DE2 verification handoff

**USB-Blaster-only option (28 October 2026):** Use the separate [JTAG board projects and replay guide](../../hardware/jtag/README.md). They do not require the RS-232 adapter described in the UART instructions below. Program a JTAG `.sof`, then run `quartus_stp -t scripts/replay_jtag.tcl temperature`, `weather_speed`, or `weather_resource`. All four physical JTAG replays passed (128 inputs / 104 checked forecasts each). See [JTAG results](JTAG_IMPLEMENTATION_REPORT.md).

Physical JTAG operation is verified. The UART instructions below describe an additional transport that has not been physically checked. A powered original DE2 with Cyclone II EP2C35F672C6, its USB-Blaster connection, and an RS-232 adapter for the onboard DB9 connector are needed. The supplied image confirms the FPGA device; check the board revision against the original-DE2 pin map before programming.

## 1. Confirm connections

```bash
jtagconfig
.venv/bin/python -m serial.tools.list_ports
```

The JTAG scan must show EP2C35. USB-Blaster is for programming; it is separate from the RS-232 data interface. Record the cable and serial port actually found. The commands below assume cable index 1; replace it if necessary.

## 2. Temperature version

From the repository root:

```bash
quartus_pgm -m jtag -c 1 -o 'p;hardware/quartus/de2_temperature/output_files/temperature.sof'
```

Hold and release KEY0 after programming, then run with the actual adapter port:

```bash
.venv/bin/python scripts/replay_temperature_board.py --port /dev/ttyUSB0 --samples 128
```

Acceptance: 104 forecasts match bit-for-bit, with correct packet headers/checksums and no timeout. The CSV is written to `docs/reports/board_temperature.csv`.

## 3. Weather version

Program the parallel implementation:

```bash
quartus_pgm -m jtag -c 1 -o 'p;versions/weather_v2/quartus/de2_speed/output_files/weather_board.sof'
```

Hold/release KEY0, then:

```bash
.venv/bin/python versions/weather_v2/software/replay_board.py --port /dev/ttyUSB0 --limit 128 --output versions/weather_v2/reports/physical_parallel.csv
```

Repeat for the shared implementation, resetting KEY0 after programming:

```bash
quartus_pgm -m jtag -c 1 -o 'p;versions/weather_v2/quartus/de2_resource/output_files/weather_board.sof'
.venv/bin/python versions/weather_v2/software/replay_board.py --port /dev/ttyUSB0 --limit 128 --output versions/weather_v2/reports/physical_shared.csv
```

Acceptance per implementation: 104 frames have six bit-exact scalar/component forecasts and valid checksums. The direction angle matches the independent atan2 reference within five Q8 angle units (approximately 0.0195°), with the correct undefined-direction flag for a zero vector.

## 4. Preserve physical evidence

Save JTAG/programming output, each replay CSV, the programming-file hashes, and a short recording showing the connected board and result. Update the report only after the physical checks succeed. If a check fails, preserve its log and diagnose it before claiming board operation.

The replay vector file is generated by `versions/weather_v2/software/make_vectors.py`. Forecast metrics on the held-out test dataset are separate from these bit-exact communication/implementation checks.

The user confirmed that the board is not available on this computer. Physical acceptance therefore requires later access to the board; the supplied replay tools and programming files are prepared for that step.

## Vendor timing-simulation acceptance

All four core SDF timing checks have passed at 50 MHz. The following commands reproduce them. The Icarus vendor timing-model elaboration failed, and XSim probes produced mismatches/timing violations; those failures are preserved in the report evidence. ModelSim-Altera Starter Edition 10.1d is now installed with a local 32-bit ncurses compatibility library. The installation checksum and paths are recorded in `modelsim_installation.json`. Run from the repository root:

```bash
source scripts/modelsim_env.sh
.venv/bin/python scripts/run_modelsim_timing.py --design temperature_speed
.venv/bin/python scripts/run_modelsim_timing.py --design temperature_resource
.venv/bin/python scripts/run_modelsim_timing.py --design weather_speed
.venv/bin/python scripts/run_modelsim_timing.py --design weather_resource
```

The script generates a separate original Quartus timing netlist/SDF, applies max delays, and rejects transcripts with timing violations or no explicit scoreboard PASS. Do not replace the existing functional-netlist evidence with an unverified SDF claim.
